# NexaGram — Firebase Setup

This guide takes you from an empty Firebase project to a working NexaGram
backend: Authentication, Firestore, Storage, Cloud Messaging, security
rules, indexes, and the one required Cloud Function.

---

## 1. Prerequisites

- A Google account and access to the [Firebase console](https://console.firebase.google.com)
- Node.js 18+ (for the Firebase CLI and the Cloud Function)
- The Flutter SDK already set up for this project (`flutter doctor`)

Install the CLIs once, globally:

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
```

---

## 2. Create the Firebase project

1. Go to the [Firebase console](https://console.firebase.google.com) → **Add project**.
2. Name it (e.g. `nexagram-app`). Google Analytics is optional — the app
   depends on `firebase_analytics`, so leave it enabled unless you plan to
   remove that dependency.
3. Wait for provisioning to finish.

---

## 3. Register your apps and generate `firebase_options.dart`

From the project root (`nexagram/`):

```bash
firebase login
flutterfire configure --project=<your-project-id>
```

Select **iOS** and **Android** when prompted (add macOS too if you plan to
ship it). This does two things:

- Registers each platform's app in the Firebase console for you.
- Overwrites `lib/firebase_options.dart` with real `apiKey`/`appId`/
  `projectId` values, replacing the placeholder in this repo.

It also drops `android/app/google-services.json` and
`ios/Runner/GoogleService-Info.plist` — both are already covered by
`.gitignore`, so they won't accidentally get committed.

**Bundle/Application ID:** this repo ships with the Flutter-default
`com.example.nexagram` in `android/app/build.gradle.kts` (`applicationId`
and `namespace`) and `android/app/src/main/kotlin/.../MainActivity.kt`
(package declaration). Before running `flutterfire configure`, decide on
your real identifier (e.g. `com.yourcompany.nexagram`) and update all
three of those in lockstep, plus the iOS bundle identifier in Xcode
(Runner target → **Signing & Capabilities** → Bundle Identifier) — they
must match what you register in Firebase for each platform.

---

## 4. Enable Authentication

Console → **Build → Authentication → Sign-in method** → enable
**Email/Password**.

That's the only provider the current codebase uses
(`AuthService` calls `signInWithEmailAndPassword` /
`createUserWithEmailAndPassword`). Adding Google/Apple/phone sign-in later
is a matter of enabling the provider here and adding the corresponding
`firebase_auth` calls to `AuthService`.

---

## 5. Create Cloud Firestore

Console → **Build → Firestore Database → Create database**.

- Choose a region close to your users (this cannot be changed later).
- Start in **production mode** — the rules in this repo (`firestore.rules`)
  replace the default deny-all as soon as you deploy them (step 8).

### Data model

| Path | Written by | Notes |
|---|---|---|
| `users/{uid}` | `AuthService`, `UserService` | Profile, presence, FCM tokens. See `UserModel`. |
| `usernames/{usernameLower}` | `AuthService.register` | Uniqueness reservation: `{ uid }`. Never updated/deleted. |
| `users/{uid}/contacts/{contactUid}` | `ContactService` | One-directional saved contacts. See `ContactModel`. |
| `chats/{chatId}` | `ChatService` | Private chat id = sorted `uidA_uidB`; group chat id = auto. See `ChatModel`. |
| `chats/{chatId}/messages/{messageId}` | `ChatService` | See `MessageModel`. Deletes are soft (`isDeleted: true`). |
| `chats/{chatId}/typing/{uid}` | `ChatService.setTyping` | Ephemeral; deleted when typing stops. |
| `reports/{reportId}` | (future: report/block UI) | Write-only from the client; reviewed out-of-band. |

All collection/field names are centralized in
`lib/core/constants/app_constants.dart` (`FirestoreCollections`) — if you
rename anything, change it there rather than hunting through service files.

---

## 6. Create Firebase Storage

Console → **Build → Storage → Get started**. Use the same region as
Firestore. Start in production mode (rules deployed in step 8 govern
access).

### Bucket layout

| Path | Written by | Limit |
|---|---|---|
| `avatars/{uid}.jpg` | `StorageService.uploadAvatar` | 10 MB, image only |
| `chats/{chatId}/images/{fileName}` | `uploadChatImage` | 10 MB, image only |
| `chats/{chatId}/files/{fileName}` | `uploadChatFile` | 50 MB |
| `chats/{chatId}/voice/{fileName}` | `uploadVoiceMessage` | 50 MB, audio only |

These paths are generated by `StoragePaths` in `app_constants.dart` and
must stay in sync with `storage.rules`.

## 7. Enable Cloud Messaging (push notifications)

Console → **Build → Cloud Messaging**. No extra setup is required for
Android. For iOS:

1. Enroll in the [Apple Developer Program](https://developer.apple.com/programs/) if you haven't.
2. Create an APNs authentication key (or certificate) in the Apple
   Developer portal.
3. Upload it under **Project settings → Cloud Messaging → Apple app
   configuration**.
4. In Xcode, enable **Push Notifications** and **Background Modes →
   Remote notifications** under the Runner target's **Signing &
   Capabilities** (the latter is already declared in
   `ios/Runner/Info.plist` via `UIBackgroundModes`).

The client side (`NotificationService`) already requests permission,
registers/refreshes the device's FCM token onto `users/{uid}.fcmTokens`,
and shows foreground notifications — there's nothing else to change in
Dart. What's still needed is a **server-side sender**, since Cloud
Messaging doesn't deliver pushes on its own trigger — see the Cloud
Function below.

---

## 8. Deploy security rules and indexes

From the project root:

```bash
firebase use --add          # link this folder to your Firebase project
firebase deploy --only firestore:rules,firestore:indexes,storage
```

This deploys `firestore.rules`, `firestore.indexes.json`, and
`storage.rules`, all included in this repo and already scoped to match
exactly what the app's service classes read and write. Re-run this
command any time you change a rule or add a new query that needs a
composite index (Firestore's error message includes a direct console
link to auto-generate the missing index definition, which you can then
copy into `firestore.indexes.json` to keep it versioned).

To test rules locally before deploying:

```bash
firebase emulators:start --only auth,firestore,storage
```

## 9. Cloud Functions (server-side work the client can't safely do)

Two things intentionally live server-side rather than in the Flutter app,
because Firestore security rules can't express them (recursive deletes)
or because they need the Admin SDK's elevated privileges (sending pushes
on another user's behalf):

### a) Recursive delete of a chat's messages

`ChatService.deleteChat` only deletes the `chats/{chatId}` document —
client SDKs cannot recursively delete a sub-collection, and doing it
message-by-message from the client would need broad delete permissions
that the security rules deliberately don't grant. Add:

```bash
firebase init functions   # choose TypeScript or JavaScript
```

```ts
// functions/src/index.ts
import { onDocumentDeleted } from "firebase-functions/v2/firestore";
import { getFirestore } from "firebase-admin/firestore";
import { initializeApp } from "firebase-admin/app";

initializeApp();

export const cleanupChatMessages = onDocumentDeleted(
  "chats/{chatId}",
  async (event) => {
    const db = getFirestore();
    const messagesRef = db
      .collection("chats")
      .doc(event.params.chatId)
      .collection("messages");
    const snapshot = await messagesRef.get();
    const batchSize = 400;
    for (let i = 0; i < snapshot.docs.length; i += batchSize) {
      const batch = db.batch();
      snapshot.docs.slice(i, i + batchSize).forEach((doc) => batch.delete(doc.ref));
      await batch.commit();
    }
  }
);
```

### b) Sending the actual push notification

`NotificationService` registers each device's FCM token, and the client
displays a *local* notification when a message arrives while the app is
in the foreground — but nothing yet sends a push to an *offline*
recipient's device. Add a trigger that fires on new messages and pushes
to every other participant's tokens:

```ts
// functions/src/index.ts (continued)
import { onDocumentCreated } from "firebase-functions/v2/firestore";
import { getMessaging } from "firebase-admin/messaging";

export const notifyOnNewMessage = onDocumentCreated(
  "chats/{chatId}/messages/{messageId}",
  async (event) => {
    const message = event.data?.data();
    if (!message) return;

    const db = getFirestore();
    const chatDoc = await db.collection("chats").doc(event.params.chatId).get();
    const chat = chatDoc.data();
    if (!chat) return;

    const recipients: string[] = chat.participantIds.filter(
      (uid: string) => uid !== message.senderId
    );
    if (recipients.length === 0) return;

    const usersSnap = await db
      .collection("users")
      .where("__name__", "in", recipients.slice(0, 30)) // whereIn caps at 30
      .get();

    const tokens = usersSnap.docs.flatMap((d) => d.data().fcmTokens ?? []);
    if (tokens.length === 0) return;

    const senderSnap = await db.collection("users").doc(message.senderId).get();
    const senderName = senderSnap.data()?.name ?? "New message";

    await getMessaging().sendEachForMulticast({
      tokens,
      notification: {
        title: senderName,
        body: message.type === "text" ? message.text : "Sent an attachment",
      },
      data: { chatId: event.params.chatId },
    });
  }
);
```

Deploy with:

```bash
firebase deploy --only functions
```

## 10. Seed data / smoke test

After steps 1–8, run the app against the emulators first so you don't
need real device tokens to verify auth/Firestore/Storage wiring:

```bash
firebase emulators:start --only auth,firestore,storage
flutter run --dart-define=USE_FIREBASE_EMULATOR=true
```

(The `USE_FIREBASE_EMULATOR` flag is a suggestion, not wired up yet — if
you want emulator support, point `AuthService`/`ChatService`/
`StorageService`'s underlying instances at
`FirebaseAuth.instance.useAuthEmulator(...)` /
`FirebaseFirestore.instance.useFirestoreEmulator(...)` /
`FirebaseStorage.instance.useStorageEmulator(...)` during `main()` when
that flag is set.)

Register two accounts, add each other as contacts, start a chat, send a
text message and an image, and confirm:

- Both `users/{uid}` docs exist with `usernameLower`/`nameLower` set.
- `usernames/{usernameLower}` was reserved.
- `chats/{chatId}` was created with the correct deterministic id.
- `chats/{chatId}/messages` has your message and `chats/{chatId}
  .unreadCounts` incremented for the recipient.
- The uploaded image appears under `chats/{chatId}/images/` in Storage.

- [ ] Replace the default `com.example.nexagram` application id / bundle id (step 3)
- [ ] `firestore.rules`, `firestore.indexes.json`, and `storage.rules` deployed
- [ ] Email/Password sign-in enabled
- [ ] APNs key uploaded (iOS push)
- [ ] `cleanupChatMessages` and `notifyOnNewMessage` functions deployed
- [ ] Real app icons/launch screens in place (currently Flutter's defaults)
- [ ] SF Pro Display font files added under `assets/fonts/` (see
      `pubspec.yaml`'s `fonts:` section) — the app falls back to Google
      Fonts' Inter automatically if these are absent, so this is cosmetic
      polish, not a blocker
- [ ] Firebase Analytics reviewed for your privacy policy / App Store
      "privacy nutrition label" disclosures, since `firebase_analytics`
      is included in `pubspec.yaml`
